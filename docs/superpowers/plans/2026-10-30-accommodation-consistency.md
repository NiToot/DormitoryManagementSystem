# 第三阶段住宿一致性实施计划

**目标：** 入住分配、退宿、房间更新与调宿审批原子提交；并发请求不能重复入住、覆盖已占床位或重复审批。

**设计：** 保留四床位模型。新增单行数据库写锁，由 Spring 事务取得并持有到提交，协调所有应用实例的住宿写入、调宿申请写入、学生/楼宇删除。房间和申请增加 version，客户端携带读取版本，过期操作返回 409。此规模下先选择易验证的串行写事务；读操作不取得全局写锁，后续写吞吐增长时再改为按学生和房间有序加锁。

**边界：** 沿用第二阶段权限；不切分支、不暂存、不提交、不推送；仅本机 13306 专用演示库。直接在数据库执行 SQL 的外部写入不受应用协议保护。历史冲突只报告，不猜测删除数据。
